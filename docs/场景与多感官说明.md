# 场景与多感官说明

本机实验场默认使用“综合觅食场”，包含主要糖水、果味食物、水源、危险区、亮区、阴影和中性对照。围墙与两处实体障碍保留原来的 MuJoCo 接触与碰撞。各区域用简单立体造型标记，造型没有新增碰撞，不会抬起、移动或重置果蝇。

## 地图怎么编辑

在“场地与轨迹”中选择类型，调整名称、半径与强度，点击“点击地图新增”，再点击空地放置。普通点击已有区域可以选中它；也可以用下拉框选择。选中后可移动、修改属性或删除。编辑在运行或暂停时均可提交，不需要重开脑模型。

- 最多 24 个元素；半径 0.8–4 mm，强度 0–1，名称最多 24 个字符。
- 元素必须完整位于围栏内，距边界至少 1 mm，并避开实体障碍。
- 食物、水源、危险区和对照区不能相互覆盖；亮区与阴影可以叠加。
- 主要食物不能删除，可移动、改成糖水/果味或把强度调为 0。强度 0 仍保留标记，但不产生该区的感觉输入。
- 等待“场景修改已应用”。非法修改会说明原因，不会偷偷换位置。
- 刷新网页会读取当前场景；“按初始配置开始新一轮”会重新初始化脑、身体和默认七区，上一轮记录保留。

## 元素与输入

| 元素 | 三维造型 / 地图图标 | 输入与当前工程反馈 |
| --- | --- | --- |
| 糖水食物 | 托盘上的奶白糖块 / 糖块 | 糖气味场；足部接触甜味，满强度时给既有 21 个糖 GRN 输入 200 Hz，并触发停留规则 |
| 果味食物 | 红橙水果与绿叶 / 水果 | 独立果味通道，加少量糖气味；足部甜味强度 0.6，满强度糖 GRN 输入 120 Hz |
| 水源 | 不规则蓝色水洼与反光 / 水滴 | 湿度代理场与实际足部区域接触；工程湿度趋向，接触后减小运动命令 |
| 危险区 | 三角感叹号警示牌 / 警告三角 | 排斥气味、温度代理场、足部苦味；梯度引导回避，苦味或较高温度触发短时后退 |
| 亮区 | 黄色灯泡与灯柱 / 灯泡 | 增加亮度代理场，工程策略趋向较亮一侧；标记也进入实际复眼画面 |
| 阴影区 | 青绿色遮阳棚 / 遮阳伞 | 降低局部亮度代理场；可叠加其他区域做对照 |
| 凉区 / 冰块（可新增） | 蓝白冰块 / 雪花 | 中心约降低 10 °C 的局部温度代理，少量湿度；没有冷却物理 |
| 中性对照 | 黑白棋盘格地砖 / 棋盘格 | 可见标记与区域接触记录，不额外产生气味或甜/苦味 |

地图虚线圈表示原来的作用范围，图标表示类别；点击圈内仍可选中元素。立体造型会进入实际复眼，新增、删除、缩放及切换类型均同步更新。造型只是辨识标记，甜味/水接触仍按圆形区域采样；灯与棚没有新增真实照度或遮挡求解。更改外观可能改变复眼像素和视觉避障响应。

强度按 0–1 缩放上述场或接触输入。主要食物的气味标准差保持原来的 13 mm；其他元素的范围随半径变化。温度代理以 25 °C 为背景，满强度危险区中心增加约 12 °C。这些数值是工程设定，不是果蝇实验标定值。

## 实际采样与简化模型

**复眼**：仍使用实际 MuJoCo 眼相机、鱼眼变换与每眼 721 个小眼采样。区域的增删、移动和缩放会同时改变 MuJoCo 标记、网页三维、俯视地图及复眼画面。网页没有额外替身体算运动。

**触角场**：在两个实际触角位置采样糖气味、果味、排斥气味、亮度、湿度和温度的二维标量场。气味和湿度用高斯场，明暗和温度用局部代理场；没有模拟气流、扩散输运、遮挡、辐射测量或热传导。亮度代理不是从复眼像素反推的真实照度，与视觉通道是独立的工程输入。

**足部接触**：用实际足部位置、足部高度及区域半径判定甜味、苦味、水源接触。这是几何接触采样，没有受体或水体物理。水源不模拟流动、浮力、湿润材料或饮水代谢。

**进入脑模型**：糖味沿用已接入的糖 GRN 输入；其他新增反馈通过明确的工程策略改变 P9 刺激和运动方向。没有声称接通完整的嗅觉、湿度、温度、苦味或趋光神经通路，感觉通路本身未实现神经可塑性；后续外置气味学习见行为说明。

## 感官开关与观察

“感觉输入与运动输出”中新增“多感官输入”。可分别关闭亮度引导、湿度/水源反馈、温度回避、苦味回避。原有气味开关同时关闭糖、果味和排斥气味输入；原有糖味、视觉、实体避障开关保留。

关闭某个反馈后，标记仍然可见，其他通道仍可响应；例如关闭亮度引导不会删除复眼中的亮色标记。关闭温度、苦味后，危险区还可能通过排斥气味引发回避。原始采样与启用后的通道值分别记录，避免把关闭的输入误认为场地本身消失。

“距最近有效食物”使用身体到所有强度大于 0 的糖水/果味中心的最近距离。食物接触时间包含两类食物，不再只统计主要食物。足部水源接触一栏标明原始采样。

## 记录与旧场景

- `config.json`：初始七区、感官开关和运行参数。
- `events.jsonl`：每次场景修改的完整布局、原请求、模型时间和 `arena_revision`；感觉开关保留为命令事件。
- `senses.jsonl`：每个计算块后的原始通道 `channels_raw`、启用后的 `channels` 和场景修订号。
- `report.json`：最终场景 `arena_final` 与修订号；其他脑活动、轨迹、复眼与录像记录继续保留。

需要旧的两区场景与原工程反馈基线时，在本机项目目录运行 `Start-Habitat.cmd --arena classic`；默认不传该参数就是综合觅食场。旧场景仍可编辑区域，但新增明暗/湿度/温度/苦味反馈在该基线模式关闭。

按用户要求，这次只更新本机项目和文档，未重建交付压缩包。


扩展行为现可使用上述输入进行需要驱动的觅食、寻水、明暗与温度趋向、风向引导及气味学习；说明见 [行为与感官驱动说明](行为与感官驱动说明.md)。默认布局仍为七区，冰块可手动新增。
