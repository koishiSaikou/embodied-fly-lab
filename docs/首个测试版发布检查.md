## 结论与检查范围

当前功能已经足够组成首个 Windows 公开测试版：三维身体、全连接组规模的统一 LIF 计算、真实复眼采样、脑活动观察、可编辑多感官场地、递质来源增益和外置气味偏好学习均已有实现。首发重点应转向安装可复现、故障提示、长时间运行、许可来源和版本一致性。

本次检查读取了源码、启动与打包脚本、依赖快照、中文文档、目录体积和已有验证记录，并核对 GitHub 官方发布限制。没有修改仿真代码、运行新性能测试、停止现有实验、初始化或推送 Git，也没有重建交付包。因此以下“待验收”不能理解为已经修复或通过。

现有 `docs/验证记录.md` 和 `output/behavior/全链路验证.json` 记录了本机真实 CUDA 闭环、暂停编辑、清洁、学习、重开和界面短测。尚不能据此宣称不同显卡、独立干净电脑或长时间连续运行均已验证。

## 发布前应完成

### 1. 制定源码仓库收录清单

当前根目录未见 `.git`、根级 `.gitignore` 或 `.github` 配置。整个工作目录约 31.7 GiB，主要包含本地虚拟环境、缓存、模拟接收方安装目录和历史交付物，不能整目录提交。

建议排除 `.venv/`、`.brain-venv/`、`.cache/`、`.package-cache/`、`.package-test/`、`dist/`、`output/`、`__pycache__/`、临时日志、PyTorch wheel 和可再生成的 `weight_coo.pkl` / `weight_csr.pkl`。排除仅表示不纳入 Git，不应删除本地实验记录。

需要保留并明确管理的内容：本项目源码、网页本地资源、中文文档、许可与来源、必要的上游源码和本地补丁、固定版本的数据获取清单、可重复执行的验证脚本。确认 `flygym`、`brain-model`、`fly-brain` 三个目录各自用途，避免重复收录和让使用者误认上游完整工程就是本项目入口。

连接表本身约 96.1 MiB，已接近普通 Git 文件上限；权重缓存各约 288 MiB，应由本地生成。PyTorch wheel 约 2.56 GiB，继续由用户从官方单独下载。GitHub 普通仓库阻止大于 100 MiB 的文件；Release 单个附件须小于 2 GiB，未来运行包若超过附件限制，应拆分或分离数据包并提供校验清单。[普通 Git 限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)、[Release 限制](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

验收：待提交清单无虚拟环境、缓存、个人实验和安装大文件；干净检出后能按数据清单恢复所需资产。

### 2. 补齐从 GitHub 源码安装的路径

当前源码入口与离线交付包安装方式不同：

- 根目录 `Start-Habitat.cmd` 直接调用已存在的 `.venv`。
- `delivery/bootstrap.py` 依赖交付包生成的 `_runtime`、`_tools/uv.exe`、`requirements/*lock.txt`、`bundle-manifest.json` 和 wheel 目录，不能直接当作源码安装器。
- `requirements-body-installed.txt:14` 包含 `-e file:///E:/workspace/FlyWire/flygym`；`requirements-brain-installed.txt:16` 包含本机 E 盘 torch wheel 路径。这两个文件是本机环境快照，不能直接作为公共安装说明。
- `build_windows_package.py` 当前依赖本机解释器和 `.package-cache/wheels`，尚不能从全新检出直接重现交付包。

应提供项目内安装脚本和可移植的两套锁定依赖，明确 Python 3.13 身体/网页、Python 3.12 脑模型及固定 CUDA wheel 的分工；沿用不修改系统 Python、全局 PATH 和全局包的约定。数据与依赖下载固定版本/提交、大小、SHA256 和落盘位置，缺少文件时说明缺什么、去哪下，不应继续执行后才报栈。

验收：在一个没有现有虚拟环境、缓存和个人目录依赖的独立 ASCII 路径，按公开说明完成安装、自检、启动和保存退出。记录实际 Windows、驱动和 GPU；其他平台标为未验证。

### 3. 修复启动器与网页打开行为的冲突

根目录 `Start-Habitat.cmd:7` 和 `delivery/launch.py` 的场景入口都会传 `--headless`；但 `habitat.py:236` 只有在未使用 `--headless` 时才调用浏览器。因此文档承诺的“自动打开网页”在这两条路径上都不会执行。

应让“无 MuJoCo 原生窗口”和“是否自动打开浏览器”分别受对应参数控制，网页服务就绪后再打开地址；统一源码与交付包的启动入口、端口冲突处理、缺失环境提示和日志位置。

验收：双击只启动一个实例，默认自动打开实际端口，`--no-browser` 有效；端口占用、缺环境和缺数据时提示明确；Ctrl+C 完成保存并退出。

### 4. 补脑进程超时与可靠收尾

`habitat.py:58` 和 `habitat.py:70` 对脑子进程使用阻塞 `readline()`，没有启动或单步响应期限。若子进程仍存活但不返回，主循环可能一直等待。网页虽然有断线重连，却无法用重连解决后端计算等待。

应分别设置适合首次加载与正常积分的期限，给出“加载中/计算中/超时/已停止”的具体状态，保存最近成功时间和错误摘要。错误停止后保留已有记录，重开实验需要显式操作；不要静默重置脑状态伪装恢复。

`habitat.py:402` 起的收尾按顺序执行渲染、编码器关闭、脑进程关闭和报告写入；其中某一步失败可能阻断后续清理。应隔离清理错误，让核心日志、报告及子进程回收尽量独立完成，并记录原始失败原因。

验收：受控模拟脑退出、无响应、渲染失败和保存失败，均能得到可理解的提示与可用的部分记录；正常暂停不能被误判为计算超时。

### 5. 给持续实验增加内存和磁盘边界

`habitat.py:172–173` 创建完整 `rows`、`trail` 列表；`367`、`376` 行每个计算块追加。虽然网页只发送最近 3000 个轨迹点，后端列表没有上限。默认持续运行还会不断写视频、感官、行为和复眼记录。

应流式保存完整数据，内存只保留有界显示窗口；结束报告中的最小朝上值等改为增量统计，静态图从采样数据或文件生成。提供“摘要/标准/详细”记录选项、录像开关及磁盘剩余空间提示，磁盘不足时尽可能保存并明确停止。不要自动删除历史实验。

验收：连续运行观察进程内存、输出增长和剩余空间，至少覆盖一次长实验及多次同服务重开；内存不再因轨迹条目无限增长，低磁盘模拟不破坏既有记录。积分步长与精度保持当前设置。

## 最值得补的使用功能

| 优先级 | 功能 | 最小可用范围 |
| --- | --- | --- |
| 高 | 实验预设保存与载入 | 同时保存场景、感官开关、脑/递质/行为参数、需要初值和随机种子；载入前校验，明确是新实验配置，不是恢复脑状态 |
| 高 | 一键诊断与问题报告 | 复用现有 doctor/self-test，汇总应用版本、GPU、运行状态和最近错误；导出前展示内容，避免默认带上个人实验和完整个人路径 |
| 中 | 历史实验浏览与回放 | 从记录重画轨迹、活动及行为时间轴，不必重新运行 CUDA；视频回放与神经状态恢复分别说明 |
| 中 | 对照实验 | 同一初始配置/种子切换视觉、学习或递质增益，比较首次接触食物时间、路径、碰撞和活动统计；提供重复实验汇总，不仅展示单次曲线 |
| 中 | 行为解释 | 面板显示当前状态、主导感觉、需要值、奖励/惩罚、工程规则贡献及实际脑输出，帮助理解为何停留、转向或惊逃 |

这些使用功能中，预设最适合进入首版；历史回放、批量对照可以后续版本实现。飞行、求偶、多只果蝇、完整 VNC 和全脑突触可塑性属于独立大功能，不建议作为首个 Alpha 的完成条件。
