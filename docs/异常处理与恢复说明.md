# 异常处理与恢复

适用于本独立源码目录的 `Start-Habitat.cmd` 多感官实验场。按用户后续要求，同样功能已备份后同步到现有本机项目，验证见 [功能同步验证](功能同步验证.json)；旧交付包保持原样。`Start-Coupled.cmd` / `Start-Activity.cmd` 的旧固定刺激演示尚未迁入本次脑通信期限机制。

## 脑计算的等待期限

首次启动脑进程允许等待 **300 秒**，每次发送脑积分请求后允许等待 **30 秒**。均使用真实经过的秒数，不改变模型积分步长、刺激、权重或放电统计。首次生成稀疏缓存可能较慢，可以明确调大启动期限：

```powershell
.\Start-Habitat.cmd --brain-startup-timeout 600 --brain-step-timeout 60
```

期限须大于 0、至多 3600，拒绝无穷、NaN 和负数。数值过小会把正常但较慢的机器判为超时，不会使计算更快。网页显示正在等待的阶段、已等待真实秒数和期限。暂停不发送脑请求，因此暂停本身没有这个期限。

超时也包括脑请求写入管道卡住。脑进程提前退出、管道损坏、返回坏 JSON 或缺少必要计算字段，同样明确报错。错误响应不会当成正常活动，也不会用预测值补齐。

## 出错时会发生什么

程序停止本轮推进，网页显示“正在收尾保存”，禁用重开；随后分别尝试保存末帧、关闭渲染与录像、回收本轮脑进程、关闭各记录文件、绘图和写报告。一个步骤失败会记入错误列表，并继续尝试后续步骤。

默认启动方式带 `--keep-open`，异常收尾后保留网页及最后成功的数据，并显示错误原因。没有完成第一块计算时也能看到错误及本轮目录。页面中的最后成功活动不会伪装成仍在更新。模型时间只代表完成的计算；报告分别记录最后完成的身体时间和脑响应时间，两者可能相差一个块。

确认记录后，可点击“开始新一轮”：初始化新的身体、脑和记录目录。旧记录保留。这是重新实验，**不支持恢复失败时的膜电位或接着未完成的一步计算**，也不会自动重开掩盖异常。如果脑进程/通信线程未能回收，页面禁止原地重开，应先关闭对应服务并检查本轮日志。

不带 `--keep-open` 的直接运行、或使用有限实验的 `--exit-when-finished` 时，异常收尾后退出码为 **1**。保留错误网页时，关闭该网页服务后才返回失败码；手动新开且新一轮正常结束，则由新一轮的结果决定退出码。Ctrl+C 仍先保存后退出；仅关闭浏览器不会停掉后端。

正在等待脑响应时，网页暂停/结束命令在当前请求返回后处理；若脑已卡住，最多先等本次期限，再进入异常收尾。请不要用反复点击代替等待，也不要直接关闭仍在保存的控制台。

## 去哪里查

本轮目录为 `output/habitat/时间戳/` 或指定的 `--run-name`。优先查看：

| 文件 | 内容 |
| --- | --- |
| `report.json` | 状态、身体时间、最近成功脑时间、原始异常及独立收尾错误列表 |
| `brain_worker.log` | CUDA 脑进程的标准错误，包括上游加载/计算异常 |
| `trajectory.csv`、`neural.jsonl` 等 | 已经成功写出的部分轨迹、神经、感觉和行为记录 |
| `monitor_snapshot.json` | 保存阶段的最后网页状态；并非可恢复脑状态的检查点 |
| `error.json` | 收尾/报告写入失败时，另一次独立尝试的诊断记录 |
| `output/launch/*.log` | 共享启动器收集的完整控制台输出，含错误摘要与报告内容 |

报告先写同目录 `.partial` 文件，完整写出后才替换正式文件。保存失败时可能留下 `.partial`，请将其视为不完整文件。磁盘满、权限错误或系统强制杀进程时，不能保证这些文件全部存在；程序仍尝试其他记录途径，并在控制台和仍可用的网页保留错误，不宣称已完整保存。不要删除原有记录来自动腾空间。

## 保存后的查看和条件复用

本机源码新增 `/records` 与 `View-Records.cmd`，支持历史数据查看、完整数据/配置 ZIP 交换和条件复用。`manifest.json` 成功生成后才移除 `.recording`；清单失败保留标记并显示错误，不能把未完成保存的一轮导出为完整包。旧记录没有清单也可在导出 ZIP 时生成，不改写旧目录。

这是条件复现，不改变以上“新一轮不是完整神经检查点”的边界。详见[实验保存与分享说明](实验保存与分享说明.md)。这些新增功能没有在本轮运行安装、仿真或 GPU 验证，历史验证结果不覆盖它们。

## 验证与边界

验证证据见 [异常恢复验证](异常恢复验证.json)。`tests/test_recovery.py` 使用明确标记的合成子进程验证通信、退出和写入失败；`tests/recovery_live_check.py` 在独立端口运行真实网页/身体，分别注入卡住、提前退出、坏返回、渲染关闭与报告保存失败，并验证实际 CUDA 暂停和手动重开。

本次只约束脑子进程的请求等待及独立收尾。它不为 MuJoCo 驱动、磁盘系统调用、编码器或操作系统强制结束提供通用的抢占期限，也不等于长时间资源增长已经解决。所有故障注入只针对测试自己创建的进程和目录。
