# Demo 发布前准备与操作

目标：v0.1.0-alpha.1 的公开源码 pre-release。长时间运行保护暂缓；维护者不要求本轮新增/执行测试、CI 或完整产品验收。本页不是新的测试清单。

## 已准备

中文使用入口、安装/操作/限制说明、应用身份、更新记录、许可全文、第三方范围、数据署名、引用和发布说明草稿均已整理。功能性改动已备份后同步本机；旧 ZIP 没有更新。相关记录见 `许可与版本整理记录.json`。

## 真正发布时再执行

1. 已确定公开仓库为 [koishiSaikou/embodied-fly-lab](https://github.com/koishiSaikou/embodied-fly-lab)，HTTPS 远程为 `https://github.com/koishiSaikou/embodied-fly-lab.git`。维护者创建空仓库后提供了地址，本次先上传整理后的源码。
2. 使用准备目录的源码。先查看 Git 候选清单，确保环境、缓存、实验、wheels、旧 ZIP 和被排除的原注释文档没有进入提交；这是文件范围核对，不运行仿真或测试。不要使用强制添加绕过现有忽略规则。
3. 首次源码提交保留 `unpublished-demo`（尚无 GitHub Release），推送到 main。真正创建 Release 前再将 `版本信息.json` 的 release_status 改为 demo-prerelease 并提交，同步应用身份至原本机项目。保留真实 Git SHA；同一个提交不可能预写自己的 SHA，源码 JSON 的 source_commit 可以保持 null，由 Release/分发清单记录实际提交。
4. 对选定提交建立 v0.1.0-alpha.1 标签，复制 `首次发布说明.md` 的内容创建 Release，并标为 pre-release。检查数据下载链接及许可证/引用随源码可见。
5. GitHub 生成的源码归档可用于这次源码 Demo。不要附上旧 ZIP 冒充新版本；运行包只有明确要求更新时再构建，并另核实际二进制分发条款。

本次只授权上传源码，不自动创建标签或 Release。推送成功以 GitHub main 的实际 SHA 为准，本文件不是推送完成的凭据。程序身份改动在下次正常启动后生效，不应为更新说明强行结束已有实验。仓库遵循中文文档命名，入口为根目录 `项目说明.md`；没有额外生成英文命名的 README 或 LICENSE 覆盖现有声明。

GitHub 的 pre-release 操作依据：[官方发布说明](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。
