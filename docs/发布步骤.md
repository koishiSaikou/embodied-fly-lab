# Demo 发布与交付操作

目标：v0.1.0-alpha.2，仓库 [koishiSaikou/embodied-fly-lab](https://github.com/koishiSaikou/embodied-fly-lab)，标为 **Pre-release**。维护者明确授权创建 Release，并随后要求更新 Windows 交付包；原先“不更新交付包”的本轮限制被这条新请求替代，不代表未来可自动重建。

1. 将应用身份改为 demo-prerelease，更新当前中文文档；功能/版本变化备份并同步本机原项目，保留旧实验和旧包。
2. 只核对 Git 文件范围、许可、哈希和同步账目。不运行仿真、GPU、安装、性能或长时测试。刷新仓库文件清单后提交本轮源码。
3. 从该干净提交构建版本化 Windows 运行目录及 ZIP，记录实际提交和逐文件 SHA256。保留原许可和二进制出处；两个外部 wheel 由接收方下载。打包日志在本机忽略目录保存，不作应用验收证明。
4. 推送该提交，建立 v0.1.0-alpha.2 标签并推送。用 `测试版更新说明.md` 创建非草稿 Pre-release，附新 ZIP 与 `.zip.sha256`，不附旧日期 ZIP。
5. 核对远程标签实际提交、Pre-release 状态、发布说明、附件大小与 SHA256；本机保存发布回执。发布前写下的说明不是已成功上传的证据，以 GitHub 实际结果为准。

源码 JSON 的 source_commit 保持 null，避免同一提交预写自己的 SHA；构建后的运行包身份和清单写入实际源码提交，Release 说明补充该 SHA。源码仓库保持中文文档名称，用户入口为根目录 项目说明.md。程序更新在下次正常启动生效，不为打包终止现有实验。

后续版本如需更新运行包或标签，应由维护者另行要求。长时间运行保护仍暂缓。GitHub 操作依据：[官方发布文档](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。

本版发布说明模板为[测试版更新说明](测试版更新说明.md)。历史验证JSON中记录的未提交/未推送仅表示当时阶段状态，不在发布时改写历史证据。
