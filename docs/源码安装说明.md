# Windows 源码安装说明

适用于从 GitHub 检出或下载的源码，入口是根目录 `Setup.cmd`，逻辑在 `tools/setup_source.py`。旧离线交付包的安装方式仍见操作说明，不要混用。

## 前置要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows x64，安装路径必须为 ASCII/英文，可含空格，例如 `D:\Projects\FlyWire-GitHub` |
| 身体/网页 | 已有普通 CPython 3.13 x64；本机验证 3.13.15，不使用 free-threaded / debug / ARM 版本 |
| CUDA 脑模型 | 已有普通 CPython 3.12 x64；本机验证 3.12.14，固定 PyTorch wheel 使用此 ABI |
| 安装工具 | uv 0.12.18，推荐便携 `uv.exe` 放入项目 `_tools/`，无需修改 PATH |
| GPU | 全脑需兼容该 PyTorch CUDA 构建的 NVIDIA 显卡和驱动，以真实 CUDA 自检为准；单身体无需 CUDA |
| 磁盘 | 安装器检查全模式至少剩余 12 GiB、单身体至少 2 GiB；建议预留 20 GiB 以上用于下载、缓存和记录 |

已有符合版本的 Python 直接复用；缺少版本时参考 [Python 官方 Windows 下载](https://www.python.org/downloads/windows/)自行准备，或明确指定已有便携解释器。脚本不会下载安装、升级、卸载或覆盖系统 Python，不修改全局包、全局 PATH 或注册表。不需要 WSL、CUDA Toolkit、Visual Studio、Node.js。

uv：[官方固定版本 ZIP](https://github.com/astral-sh/uv/releases/download/0.12.18/uv-x86_64-pc-windows-msvc.zip)、[官方版本页面](https://github.com/astral-sh/uv/releases/tag/0.12.18)。取出 `uv.exe` 放入 `_tools/uv.exe` 即可，不运行全局安装器；也支持 PATH 中的同版本或 `--uv "完整路径\uv.exe"`。指定解释器及隔离环境方式见 [uv 官方文档](https://docs.astral.sh/uv/pip/environments/)。

## 完整安装与启动

准备两套 Python、便携 uv，然后手动下载两个外部大文件，保留完整文件名：

| 放置位置 | 官方/固定来源 |
| --- | --- |
| `brain-model/data/2025_Connectivity_783.parquet`，100,804,642 字节 | [固定上游提交的连接表](https://raw.githubusercontent.com/eonsystemspbc/fly-brain/a3db62f9436074e485c0278290c2164ed6150808/data/2025_Connectivity_783.parquet) |
| `downloads/torch-2.11.0+cu128-cp312-cp312-win_amd64.whl`，2,753,189,216 字节 | [PyTorch 官方 wheel](https://download-r2.pytorch.org/whl/cu128/torch-2.11.0%2Bcu128-cp312-cp312-win_amd64.whl) |

精确 SHA256 见 [外部资源清单](../外部资源清单.json)。安装器会实际读取并校验；错误文件保留并报错，不会静默覆盖。神经元顺序表、已导入注释、网页分类与形态小资产已包含，无需为普通运行重新下载原始 TSV/骨架。

在项目根目录依次执行，或双击对应 CMD：

```powershell
.\Setup.cmd
.\Check-Environment.cmd
.\Start-Habitat.cmd
```

首次完整安装会按 `requirements/body-win-x64.lock.txt` 和 `brain-win-x64.lock.txt` 的固定版本、Windows ABI 和 SHA256 从 PyPI 安装全部普通依赖。FlyGym 另用锁定的 setuptools 安装本目录 `flygym/`，采用 editable 方式，修改该源码会生效。安装后可以原位重跑，不会自动删除环境。

`Check-Environment.cmd` 会编译身体模型、核对数据和执行实际 CUDA 核函数。结果在 `output/setup/diagnostics-body.json`、`diagnostics-brain.json`。

启动后保持控制台打开；网页就绪后会自动打开浏览器，默认端口被占用时会另选空闲端口，以控制台打印的实际地址为准。浏览器打开失败时可手动访问该地址。关闭时先在网页结束并保存，再到控制台按 Ctrl+C，等待保存与服务关闭。更多选项见 [启动与停止说明](启动与停止说明.md)。

只检查前置条件，不创建环境或安装包：

```powershell
.\Setup.cmd --check
```

## 单独身体模式

只需 Python 3.13、uv 和身体依赖，无需 Python 3.12、连接表、PyTorch 或 NVIDIA GPU：

```powershell
.\Setup.cmd --body-only
.\Start-Body.cmd
```

这是 CPG 身体模式，不是全脑模式；本步骤没有给网页工程基线增加新入口。

## 已有下载、显式路径与离线方式

大文件在其他目录时，校验后复制，不移动原件，也不建立硬链接：

```powershell
.\Setup.cmd --resource-dir "E:\MyDownloads"
```

该目录可直接包含两个文件，也可具有资源清单的相对目录结构。若只想让脚本下载约 96 MiB 连接表，可添加 `--download-data`；PyTorch 始终手动提供。下载超时、大小或哈希不符会停止并给出链接。

明确指定两套已有的基础解释器；不能指向其他项目的虚拟环境：

```powershell
.\Setup.cmd --python-body "D:\Python313\python.exe" --python-brain "D:\Python312\python.exe"
```

CMD 会尝试项目虚拟环境、uv 发现的基础 Python、`py` 和 `python`。若引导器仍找不到 Python，直接用完整路径执行：

```powershell
& "D:\Python313\python.exe" -X utf8 -B tools/setup_source.py --uv "_tools\uv.exe" --python-body "D:\Python313\python.exe" --python-brain "D:\Python312\python.exe"
```

普通依赖下载慢时，可先按照 [依赖来源清单](../requirements/依赖来源.json) 的文件名、直接链接和哈希备齐 wheel，再安装：

```powershell
.\Setup.cmd --offline --wheel-dir "D:\Wheels\body" --wheel-dir "D:\Wheels\brain"
```

`--wheel-dir` 可重复传入。离线方式需要锁文件中的全部 wheel，包括 setuptools 和 PyTorch，以及已有两套 Python；大文件仍使用指定位置或 `--resource-dir`。缺包直接报错，不回退到联网或更换版本。`--offline` 与 `--download-data` 不能同用。

## 隔离、故障与记录

- `.venv/`、`.brain-venv/` 是新环境，带 `.source-environment.json` 所有权标记；脚本拒绝修改不带本安装器标记的既有环境。
- `.cache/` 保存 uv、临时文件、Python/Numba、Matplotlib、CUDA 等缓存；`output/setup/` 保存 `source-install.log`、`源码安装结果.json` 和诊断。
- 运行环境、大文件、缓存和输出均被 Git 忽略。根目录旧 `requirements-*-installed.txt` 是本机历史快照，仍含旧路径，不能拿来安装；使用新的锁文件。
- 缺工具、解释器或文件时按错误提示准备后重跑；不会自动更换版本或覆盖错误文件。
- 发生包安装失败/正常 Ctrl+C 后可以原位重跑。本项目自己的包安装子进程会停止，错误记录保留。
- 强制关闭安装后如留有 `.cache/source-setup.lock`，先确认本项目没有安装进程，再手动移除这个锁并重跑；不要停止其他项目的 Python。
- 移动目录、更换基础解释器或遇到不带标记的环境时，保留原目录并用新检出重装，不自动删除或伪造标记。
- 缺驱动、系统 DLL 或 GPU 不兼容时参考 [下载说明](下载说明.md) 的官方组件链接，也可先装身体模式。脚本不代装驱动和系统组件。

## 验证边界

本机已验证全新身体与脑环境的离线安装、依赖一致性、editable 路径、实际 CUDA 核函数、身体录像、全脑刺激及 0.04 模型秒脑—身体—复眼闭环。另检查未建环境且路径带空格时的 CMD 引导和安装器保护分支，见 [源码安装验证](源码安装验证.json)。

这不等同于另一台电脑、全部 GPU、长时间稳定性或所有在线下载条件都已验证。以上是先前源码安装步骤的历史记录。后续功能改动已按维护者要求同步本机，但现有环境、原实验和旧 ZIP 不被安装步骤替换；本轮许可与版本整理没有重跑这些检查。
