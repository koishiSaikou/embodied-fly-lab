后续状态：源码安装步骤已在这个副本内完成并测试，见 [源码安装说明](源码安装说明.md)。下面“本步骤”指最初文件整理；当前本机环境/资源位于被忽略的运行目录，仍不属于 Git 收录内容。

## 排除范围

虚拟环境、所有个人实验、录像、日志、缓存、旧交付包、模拟接收方安装目录、构建输出、嵌套 `.git`、PyTorch wheel、临时下载、两份脑稀疏权重缓存不收录。原文件仍在原项目中。

约 96 MiB 的连接表、约 2.56 GiB 的 PyTorch wheel，以及重新生成注释/形态才需要的原始数据，记录在根目录 [外部资源清单](../外部资源清单.json)。本次没有实现下载器或安装器；下一步根据该清单恢复必需数据和环境。生成后的注释和网页形态已经收录，所以原始 TSV/骨架不属于普通运行的额外必需下载。

`.gitignore` 按实际路径排除运行文件。没有笼统忽略 `.pkl`、`.npy`、`.npz`，以免漏掉 FlyGym 原本需要的小型静态资产。没有创建 Git LFS 指针，也没有删除原始大文件。

`.gitattributes` 保留文件的原始字节，避免 Git 自动转换换行使快照校验失效；Windows CMD 入口必须保持 CRLF，保证检出及源码压缩下载后仍可解析。普通文本差异比较仍可使用。

## 验证与清单

[仓库文件清单](../仓库文件清单.json)记录当前每个收录文件的大小与 SHA256；`source_path` 表示仍与原项目相同的副本，`original_source_path` / `original_sha256` 表示在新目录有意修改过的副本及其原件校验凭据，其余为新增文件。清单自身及整理验证报告不参与自校验，避免循环。后续改动后运行 `python -B tools/refresh_repository_inventory.py` 更新；它是源码快照凭据，不是锁死开发文件的安装清单。

使用任意 Python 3.12+ 执行下面的标准库检查，不会安装包或生成 pyc：

```powershell
python -B tools/verify_repository.py
```

如果希望同时逐个比较原件，可以显式指定原项目目录：

```powershell
python -B tools/verify_repository.py --source ..\FlyWire
```

检查包括复制文件的字节一致性、大文件和运行垃圾排除、嵌套 Git 排除、本项目 Python 语法、Git 忽略规则，以及必要源码/默认资产是否被误忽略。Git 仓库内检查候选源码文件，被忽略的本机环境、数据和输出不会误报为待上传文件。结果见 [仓库整理验证](仓库整理验证.json)。这不是安装成功、GPU 成功或生物有效性的验证。

六项全链路脚本的新入口为 `tests/`；现有旧文档若仍引用 `output/*live_check.py`，在本副本中应改用同名 `tests/` 路径。它们仍只控制自己创建的测试进程，结果继续写入被 Git 忽略的 output；本次整理没有执行它们。
